## 修复的问题

### 1. ✅ 指标含义不明确问题

**问题描述：**
- "标准总数" 混合了标准表和术语冲突表的数据
- "本月新增" 统计了标准 + 术语冲突 + 问答对的总和
- "待处理对齐" 逻辑复杂，混合了多个数据源

**修复方案：**
- **标准文档总数**：仅统计 `Standard` 表中的记录数
- **本月新增文档**：仅统计 `Standard` 表中本月创建的记录数
- **待处理对齐任务**：统计状态为 `pending` 或 `processing` 的 `AlignmentTask` 数量

**修改位置：**
- 文件：`semAlign_backend/routers/workbench.py`
- 行号：391-411（关键指标统计）
- 行号：413-447（环比增长率计算）
- 行号：449-454（指标数据组装）

**修改后的指标标题：**
```python
metrics: List[MetricData] = [
    MetricData(title="标准文档总数", value=total_standards, unit="个", trend=trend_total),
    MetricData(title="本月新增文档", value=monthly_added, unit="个", trend=trend_new),
    MetricData(title="待处理对齐任务", value=pending_alignments, unit="个", trend=None)
]
```

### 3. ✅ 日期显示不清晰问题

**问题描述：**
- 标准动态中的两个日期都相同
- 没有区分创建时间和更新时间

**修复方案：**
- 明确显示"创建于"或"更新于"前缀
- 如果更新时间与创建时间不同，显示"更新于"
- 否则显示"创建于"

**修改位置：**
- 文件：`semAlign_backend/routers/workbench.py`
- 函数：`_recent_dynamics()`
- 行号：245-249

**修改后：**
```python
# 区分创建时间和更新时间
if s.updated_at and s.created_at and s.updated_at != s.created_at:
    time_str = f"更新于 {s.updated_at.strftime('%Y-%m-%d %H:%M')}"
else:
    time_str = f"创建于 {(s.created_at or dt).strftime('%Y-%m-%d %H:%M')}"
```

### 4. ✅ 标准动态显示内容问题

**问题描述：**
- 标准动态中混合显示了"问答对入库"和"术语冲突库导入"的信息
- 这些信息与标准文档管理无关，造成混淆

**修复方案：**
- 移除术语冲突批次（`ImportBatch`）的动态信息
- 移除问答对（`ConflictDialogue`）的动态信息
- 只保留标准文档（`Standard`）相关的动态

**修改位置：**
- 文件：`semAlign_backend/routers/workbench.py`
- 函数：`_recent_dynamics()`
- 行号：263-267

**修改说明：**
删除了以下代码块：
1. 术语冲突批次查询和添加逻辑（约30行）
2. 问答对查询和添加逻辑（约20行）

添加了注释说明：
```python
# 移除术语冲突批次和问答对的动态信息，只保留标准文档相关的动态
# 如果需要查看这些信息，应该在专门的页面中展示
```
